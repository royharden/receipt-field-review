# Current limitations

The synthetic recognized-bundle demo is available as of 2026-10-15; [development status](../DEVELOPMENT-STATUS.md) is the current
implementation inventory. Durable recognized-item B0 jobs and pure API DTO/schema/TypeScript contracts
are implemented. A recognized-bundle FastAPI adapter now enforces admission and actual stream limits in process.
FastAPI/Uvicorn/httpx are installed; recognized-bundle viewer/listener are implemented; HTTP image
worker control now has an opt-in binary staging/start/status implementation described in
[image-http.md](image-http.md). Its graceful worker drain has no hard codec shutdown deadline;
API source and runtime qualification remain separate from construction. Existing normalized local pixels can be read through the revision/grid-bound authenticated API and displayed with selected field overlays. Native image/browser qualification remains pending. An optional installed-Tesseract CLI now
executes actual local OCR on normalized images and joins canonical B0/review/export. No live
provider call or receipt-quality measurement is supplied by that functional control.

The demo's deliberate arithmetic mismatch remains review-only until explicit synthetic issue waivers
are recorded. Its final clean export means operationally resolved, including waived conflicts, not
arithmetically verified. All decisions remain agent-provisional, and missing quantity/unit-price
values are explicitly waived as absent rather than guessed. The shipped fixture's geometry and
confidence values are authored controls, despite valid source-bound schema tags. No original image
exists for this demo. See [fixture provenance](../examples/README.md).

Two earlier combined runs had unexplained five-second process-start barrier failures. A later
independent default combined run of the unchanged demo candidate passed with original deadlines,
and the narrow local slice/current gate were accepted with notes. This is not an established cause
or stable timing-reliability claim. The HTTP continuation changes source/dependencies and requires
its own checks and independent disposition; whole-app acceptance remains outstanding.

The repository contains four reusable foundations, generated schemas, a bounded rulings journal/scalar projection, generic evaluation/selection and a receipt-local B0 plugin with fixed scalar/line-cell metadata and code checks. A provided-recognized-bundle file/JSONL review workflow, CLI, durable recognized-item jobs and audited private CSV/JSONL exports are implemented. The app-local installed-engine CLI supplies basic image-to-receipt ingestion. Live model verification, live-method jobs, receipt-domain scorers, complete image UI integration and native image/browser qualification remain pending. The optional image HTTP host is a separate source construction, with its own focused and independent qualification required.

B0 over-finds candidates from supplied retained recognized lines. It supports basic line amounts and explicitly printed quantity-times-unit-price forms, plus separately printed tip/service/discount adjustments. Missing quantities, unit prices, tax, currency codes and unknown adjustment stages are not guessed. Handwriting, complex/multicolumn layouts, Arabic/localized numeral formats and real OCR quality remain unmeasured. The current presets cover USD/EUR/GBP/CAD/AUD/JPY/KWD; other currency codes are rejected. Diagnostic checks/proposals default to blank review, with no calibrated automation claim.

Fieldextract computes diagnostic scores through injected evidence/judgment/check ports and defaults to blank review values. It contains no actual source resolver, calibration authority, screen, provider SDK, budget/retry/fan-out controller or human provenance authority. Synthetic routing controls cannot authorize real automation. Raw candidate banks remain caller-owned retained inputs; normalized selected proposals alone do not preserve all raw OCR/model signals.

The Python/Node checks verify architecture and publication controls. Synthetic module tests verify schema/identity/evidence admission and moved closures. Journal tests execute bounded append/CAS/historical retries, Windows process locking/exit controls and moved runtime, with damaged bytes preserved. Evalkit controls execute hand-counted statistics, whole-group paired draws, corpus/runner/reporting failures and detached runtime. They do not prove POSIX/power-loss durability, matching graph reducers, real human identity, OCR quality, receipt-field accuracy, real-data statistical results, providers, a frontend build, browser persistence, hosted isolation or app acceptance.

Evalkit source lookup, domain adapters and callbacks are injected trusted code. Frozen bytes do not prove lawful rights or genuine human provenance; matching held-out admission references do not authenticate an independent author/seal. The caller must provide durable exposure history and actual approval. No persistent held-out history, split generator, human-label interface or live cost collector is implemented. Corpus lookup assumes an owner-controlled local directory and does not provide hostile multiuser filesystem isolation.

Authored native HEIC decode/staging is exercised separately. Required later evidence includes
a lawful real 30-item OCR comparison, browser overlay/correction/restart/stale-tab behavior, module consumer contracts and three-method measured results. Real datasets, applicable terms, human-corrected gold, and a full paid evaluation grant remain prerequisites. Synthetic/replay data cannot satisfy those real-data claims.

The declared default for 100 phone receipts is 60 dev / 40 held-out with review-only fields when the strict lower-95%-Wilson precision gate cannot be met. No measured automation or accuracy result exists yet.

Docio can parse bounded retained Tesseract-format TSV and assemble an exactly bound Page. Literal
parser controls remain separate from the app-local adapter's actual installed-engine execution.
Neither supplied engine metadata nor an authored functional case authenticates real-data quality,
lawful 30-item engine comparison or every loaded binary/model source. The native adapter is not
yet a separately published reusable Docio export closure.
Native startup and total-operation timing remain unresolved. A joined run retained native probe
and review-process timeout failures; a later moved-runtime native import also exhausted its unchanged
30-second total budget despite successful, reaped engine commands. Its four other targeted passes
do not establish timing stability, explain the earlier failures or satisfy the combined gate.

The app's ReplayOcr accepts only explicitly supplied bounded frames under an expected engine/config profile. A replay hit is not actual native execution or source/capture authority; misses cannot fall back to a paid/native operation. Authenticated HTTP reads of existing normalized local pixels are implemented with revision/grid checks. Qualification of the new image upload host, lawful capture handling and the complete image job/UI integration remain pending. Model/provider strict replay will use the canonical provider owner, rather than this OCR-specific adapter.

Python/native OCR is an external runtime boundary for the eventual static viewer. No hosted database, GitHub remote, Bolt import, backend provisioning or public release is established by this scaffold.

Canonical S3/S6 offline components are vendored unchanged and pass actual moved public controls with original apps, SDKs and network blocked. They are not yet connected to receipt methods or a live transport. Recognized-bundle workflow tests use literal synthetic sources; operational clean exports, provisional decisions and unverified human claims do not establish human Gold or measured model quality.

The new normalized-source preview has authored client/component controls for response identity,
pixel-grid overlay, fallback, stale-response refusal and object-URL cleanup. jsdom image load/error
events and transport doubles do not establish native decoding or actual browser/HTTP image behavior.
The normalized derivative, not the original container/metadata, is displayed. Source image availability
does not establish OCR accuracy, and recognized-only items continue to use the text/geometry preview.

Existing viewer and real loopback browser verification uses authored recognized bundles.
Supplied text/geometry and agent-provisional decisions do not prove original-image OCR or quality.
Capabilities and unsaved/pending decisions are memory-only, so a page reload discards unsaved work;
saved decisions replay from the local journal. Static unsaved demo mode is not implemented. A
single local Windows/Chromium journey is not a browser/OS/hosted-isolation or whole-app acceptance.

The prior viewer was not accepted after a keyboard/pending-intent source finding. The targeted
controller repair and actual React/canonical-service regression checks are separate from native
keyboard/browser loss/save observations, which remain UNKNOWN until a qualified independent scope
runs them. Earlier author-native download files do not become independent reviewer evidence.

The optional local image stager bounds encoded bytes, declared/delivered pixel counts, frame count
and normalized output. It retains metadata in the private original and strips it from the RGB PNG.
It does not sandbox native codec internals, enforce a decoder process deadline, calibrate color
conversion or provide hostile multiuser filesystem isolation. HEIC matrices start at libheif
delivered pixels; they do not recover raw container transforms. Linux codec CI and whole-app
acceptance remain unverified. Changed or partial staging output is preserved and refused.
