# Implementation lessons

- Preserve exact retained bytes separately from typed values. Integer-versus-float JSON normalization
  can change evidence identity even when values compare equal.
- Serialize source-head updates and decisions under the batch lock before the journal lock. Guard
  current revision, evidence generation, prior head and prior typed value together; isolated checks
  leave race windows. Retain exact historical retries even after rerun or deletion.
- Keep machine proposals and confidence unchanged when projecting corrections. Confirming a corrected
  value must retain its correction audit history; reopening must not revive an old correction.
- Tombstones are permanent for an identity. A new upload needs a fresh identity, not a silent restore.
- Issue waivers must bind current operand values. A corrected number does not automatically resolve
  arithmetic flags, and a future date can be reviewed while its failed check remains visible.
- Record local execution origin only at the actual extractor boundary. A queued, refused, stale or
  unavailable job must not be labeled as executed; preserve completed outcomes during interruption.
- Canonical JSON sorts opaque item keys. Tests and consumers must not infer chronological order from
  dictionary insertion order after durable serialization.
- Validate copied modules in a detached consumer with original app imports, SDKs and network blocked.
  Keep source/runtime changes distinct from test-only namespace/path adaptation and metadata newline
  differences. Tested bytes and committed bytes need explicit reconciliation when they differ.
- Preserve unsuccessful attempts and their fixes. Source/check receipts cannot retroactively prove
  a baseline that was recorded after an edit, or a check that was still running during mutation.
- Read and write text explicitly as UTF-8. A Windows default-codepage round trip can corrupt Unicode
  even when a later diff appears superficially similar.
- Package metadata, cached wheels and a pure request guard are separate from installed dependencies,
  native execution and actual HTTP enforcement. Verify each boundary with the relevant runtime.
- Provisional agent labels, claimed human actors, operational clean exports and synthetic controls
  do not establish independent human Gold, measured accuracy or calibrated automation.
- Exercise a runnable demo through public commands and durable state, then inspect both refused and
  resolved exports. A cosmetic success message can hide lost corrections, silent conflict waivers
  or altered machine evidence; verify those boundaries with fresh processes and blocked live paths.
- Pin distributed fixture bytes after Git's line-ending normalization. Compare staged blobs with
  tested working files before committing; a valid local checksum can otherwise make a clone refuse
  the same fixture. Write generated byte-pinned JSON with explicit LF handling.
- Validate the built wheel, not just editable imports. Setuptools package-data keys must be package
  names or `*`; a dotted wildcard such as `rfr.shared.*` fails current schema validation. Check actual
  archive contents for runtime schemas and copied license notices in the build gate.
- On Windows, asyncio creates a stdlib loopback socket pair for its control pipe. A blanket connect
  denial prevents event-loop initialization before the HTTP adapter runs. Permit only the scoped
  stdlib socketpair operation, keep application connects denied and test the denial after it returns.
- Use cwd-relative uv constraint paths when the installed CLI rejects an absolute Windows path with
  spaces. Preserve the failed probe; a successful alternate version is not established unless tested.
- Test an actual request stream: Content-Length admission alone cannot bound fragmented bodies,
  disconnects or stalled receives. Reconstruct the app against the same durable root to test replay.
- Starlette's outer server-error middleware sends unexpected-error responses outside user middleware.
  Set private response headers in the fallback handler too, and test the actual 500 response without
  echoing exception text or request data.
- Browser-native fetch needs its Window receiver. An injected arrow-function test double can hide
  an illegal receiver caused by calling a stored function as a class method. Bind it explicitly,
  test the receiver, and exercise the actual browser transport before claiming a working UI.
- Keep expected empty-clean refusal distinct from stale-decision conflict even when both use409.
  Show actionable omission/review guidance without implying that a clean refusal changed state.
- A disabled button is not a policy guard. Keyboard and other entry points must honor the same
  pending-intent rules; recover an uncertain result by retrying the exact retained draft rather than
  constructing another intent against a stale view. Preserve canonical CAS and historical retries.
- A saved notice can appear before state refresh finishes. In React controls, await the explicit
  operation boundary inside act before asserting reload/cancel state. A synthetic DOM event and an
  injected after-commit acknowledgement fault are distinct from native browser/network-loss proof.
- npm lock-only setup can rewrite node_modules hidden lock metadata. Record that delta separately
  from installed package code, and run isolated lock generation in the isolated runtime when exact
  preservation of the original environment metadata is required.
- Native decoders can refine dimensions while loading. Check the declared header before decoding
  and the delivered raster again before normalization; never infer raw HEIC container transforms
  from an already oriented decoder grid. Keep optional codec execution separate from OCR evidence.
- The HEIF fixture helper `from_pillow` can pre-rotate EXIF-bearing pixels before save. For a
  single container-orientation control, use the direct documented Pillow writer and inspect real
  decoded pixels; retain a failed fixture oracle rather than changing product behavior to match it.
